# Atlas cell 32r-l05 — rank class 32, algorithm family L0.5

Status: **PROPOSED** (atlas content).
Evidence level **E0 only**: every number on this page is the output of a
closed-form L0.5 analytical identity under explicit free parameters.
Nothing here is measured on hardware, no value is standard-derived, and no

## What this cell contains

The L0.5 family is the serialized-pipelined-ring AllReduce (backend
module `analytical_l05`, second frontier F1): the SAME unidirectional
ring, workload shape and equal-chunk construction as the L0 ring, with
each of the 2·(r−1) chunk transfers charged an explicit service time —
serialize the chunk at the transmitting NIC, occupy the link, one hop
latency per transfer:

    chunk size         c = M / r                       [c integral: r | M]
    one transfer       s = c/I + c/B + L               [one ring hop]
    completion time    t_L05(M, 32) = 2*(32-1)*s = 62*(M/2048 + M/2048 + 200)

At rank class 32 this family declares exactly ONE identity
(`allreduce_ring_l05` on the serialized-ring fabric
`experiments/topologies/ring32_l05_free_params.yaml`,
topology_id `ring32_l05_free_v1` — the rank-32 mirror of the rank-4,
rank-8 and rank-16 files, new in this stage); the I -> infinity limit of
the SAME identity is the L0 ring baseline itself (the module's
convergence anchor, pinned as an exact identity by the landed golden
tests), so the baseline this page deltas against is the I = infinity
member of this very family — as at rank 4, rank 8 and rank 16, the only
cell in the rank class whose baseline is an in-family limit rather than a
different algorithm.

Identity executed (per op, message M, ranks r = 32, exact Fractions):

    per-rank wire traffic  T(M, 32) = 2*(32-1)/32 * M = 31M/16            (UNCHANGED from the L0 ring — serialization moves no bytes)
    completion time        t_L05(M, 32) = 62*(M/2048 + M/2048 + 200)
                                        = 31M/512 + 12400 ns             (I = 64 bytes/ns = B)
    serialization term     t_L05 - t_L0 = 2*(32-1)/32 * M / I = 31M/1024 ns (exact, re-checked per op by the model)

Free parameters (equal across every config in this cell, and equal to
the other atlas rank classes): B = 64 bytes/ns, L = 200 ns, ranks = 32,
W1 Dense TP Decode shape (layers 2 x steps 3 = 6 AllReduce ops per
config). The family's one additional free parameter — the injection
(serialization) rate I — is fixed by the atlas fairness rule at the
registered convention value **I = 64 bytes/ns** (A-L05-INJ,
`experiments/vertical_slice/assumptions_l05.yaml`), declared on the
family's convention record [4r-l05.md](4r-l05.md): I = 64 = B, the
serializing NIC runs at link line rate. This cell's own topology file
(`ring32_l05_free_params.yaml`) carries I = 64 in-file, the rank-32
mirror of `ring8_l05_free_params.yaml` — the file the convention was
derived from. All values are free parameters or model arithmetic — none
is measured or standard-derived.

Six arithmetic facts drive the whole cell, all visible in the identities
(ring baseline: T = 31M/16, t_L0 = 31M/1024 + 12400 —
[32r-ring.md](32r-ring.md)):

1. **At I = B the serialized identity is the baseline with a doubled
   bandwidth slope: t_L05(M) = t_L0(2M) exactly** (31M/512 + 12400 =
   31·(2M)/1024 + 12400, verified at all 12 grid sizes). The latency
   chain is UNCHANGED (2·(r−1)·L = 62·200 = 12400), so both curves share
   the exact M = 0 intercept and delta(0) = 0. The doubling is visible
   digit-for-digit in the table: the L0.5 CCT column at each grid point
   equals the ring column one doubling up — eight in-grid coincidences
   (12648 = ring@8 KiB, 12896 = ring@16 KiB, 16368 = ring@128 KiB,
   20336 = ring@256 KiB, 75888 = ring@2 MiB, 139376 = ring@4 MiB,
   1028208 = ring@32 MiB, 2044016 = ring@64 MiB); the four x4 rungs of
   the ladder land off-grid (13392 = ring@32 KiB, 28272 = ring@512 KiB,
   266352 = ring@8 MiB, 4075632 = ring@128 MiB).
2. **The serialization term equals the ring's own bandwidth term at
   every M.** With I = B, 2(r−1)/r·M/I = 31M/1024 = the bandwidth term
   of t_L0 — per transfer, c/I = c/B = M/2048 (serialization and wire
   are each exactly half the non-latency transfer time). Hence the delta
   identity

       delta(M) = (t_L05 - t_L0) / t_L0 = (31M/1024) / (31M/1024 + 12400) = M / (M + 409600)

   The closed form **delta_r(M) = M/(M + L·B·r)** — the payload measured
   in units of the ring's own balance point M* = L·B·r; equivalently the
   baseline's bandwidth fraction (one minus its latency fraction). The
   rank-4, rank-8 and rank-16 cells' delta columns obey the same law
   with 51200, 102400 and 204800, so this cell exercises the law at a
   FOURTH rank class. Strictly increasing, bounded in (0, 1), delta(0) =
   0, large-M limit exactly 1.
3. **Every delta is positive — with this cell, the slower side of the
   baseline is populated at rank 32 too, by L0.5 alone.** Crossbar,
   torus (both factorizations, below the three-way crossover), doubling
   and phases all delta negative against the ring AllReduce; L0.5 pays a
   strictly positive serialization term at every M > 0 and every finite
   I, by the module's pinned convergence identity. The catalog's slower
   side is this family's alone at all four landed rank classes.
4. **M = 409600 B is now a FOUR-fold special point of the 32-rank atlas
   — the fold the 32r-phases page left pending.** After 32r-phases it
   was three-fold (ring AR balance, ring-phase balance, torus three-way
   crossover — all at M* = L·B·r = 409600 B = 400 KiB); L0.5 adds
   delta(M*) = exactly +1/2, and delta(M*) = 1/2 is rank-independent
   (structural at every r by fact 2's closed form) — the exact mirror of
   the four-fold 51200 B point at rank 4, 102400 B at rank 8 and 204800
   B at rank 16. The L0.5 identity balances its own combined
   bandwidth+serialization term 31M/512 against 12400 ns at M = 204800 B
   = M*/2, between the 128 KiB and 256 KiB grid points — and 204800 B is
   exactly the RANK-16 ring balance point: the L0.5 balance ladder
   L·B·r/2 = {25600 (r=4), 51200 (r=8), 102400 (r=16), 204800 (r=32)}
   walks the ring balance ladder one rank down, its fourth consecutive
   rung. The 32-rank transition book in units of M*/31 now reads
   {409600/31 ≈ 13212.90 (crossbar, = M*/31), 2048000/31 ≈ 66064.52
   (doubling AR and doubling phase, = 5M*/31 = log2(r)·M*/31), 204800
   (L0.5 at I = B, = 15.5M*/31 = (r−1)/2·M*/31), 409600 (ring AR, ring
   phase, torus three-way crossover, L0.5 half-point, = M*)} B — the
   ladder {1, 5, 15.5, 31} = {1, log2 r, (r−1)/2, r−1} in units of
   M*/(r−1).
5. **THE 16r-l05 PREDICTION CONFIRMED — the half-saturation shift law:
   delta_32(M) = delta_16(M/2) identically** (M/(M+409600) =
   (M/2)/(M/2+204800); verified at all 12 sizes, exact-string equal
   against the landed 16r-l05 table wherever M/2 is on its grid). The
   ladder makes it visible: the 32-rank delta column {1/101, 1/51, 1/26,
   4/29, 8/33, 16/41, 64/89, 128/153, 256/281, 1024/1049, 2048/2073,
   4096/4121} reuses the rank-16 column's entries one rung down wherever
   M/2 is on-grid ({1/51, 1/26, 8/33, 16/41, 128/153, 256/281,
   2048/2073, 4096/4121} shared); the four new entries {1/101, 4/29,
   64/89, 1024/1049} sit where M/2 crosses an x4 rung — including the
   ladder's new floor 1/101, the 1/51-analog predicted by the law. By
   the same law delta_32(M) = delta_8(M/4) = delta_4(M/8) (saturation
   in M halves per doubling of r). Consequently delta_32(M) <
   delta_16(M) at every grid size — the SAME relative serialization
   disagreement (the baseline's own bandwidth term, at every rank) is
   diluted by the longer latency chain (12400 vs 6000 ns); the ratio
   delta_32/delta_16 = (M+204800)/(M+409600) climbs 51/101 → 8217/8242
   toward 1.
6. **The absolute disagreement GROWS with rank while the relative one
   shrinks.** The serialization term itself rises from 15M/512 (r=16) to
   31M/1024 (r=32) — exactly ×31/30, the ratio of serialized transfers
   (62 = 2·31 vs 30 = 2·15) — yet fact 5 shows every delta smaller at
   rank 32. More hops to serialize over, spread over a longer latency
   chain: the delta measures the latency-chain dilution, not the term
   (the rung ladder ×7/6 (4→8) → ×15/14 (8→16) → ×31/30 (16→32) tracks
   2(r−1) exactly).

## Crossover message sizes

**None in this cell.** A crossover is a payload size where two
identities in one cell swap ordering. The cell contains one declared
finite-I identity; the family's only other member is the I -> infinity
limit, which IS the ring baseline (an exact equality, not a crossing —
the serialization term is strictly positive at every M > 0 and finite I,
zero only in the limit, so the two curves touch only at M = 0 and never
swap). Against the baseline the delta is positive and strictly
increasing on the whole grid — sign never changes, no crossing exists.
Recorded honestly rather than forced; the 32-rank catalog's non-trivial
crossovers remain the torus cell's three-way concurrent point at
M = 409600 B ([32r-torus.md](32r-torus.md)), which fact 4 above shows is
also this cell's delta = +1/2 point.
