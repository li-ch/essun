# Atlas cell 4r-l05 — rank class 4, algorithm family L0.5

Status: **PROPOSED** (atlas content).
Evidence level **E0 only**: every number on this page is the output of a
closed-form L0.5 analytical identity under explicit free parameters.
Nothing here is measured on hardware, no value is standard-derived, and no
claim or label elsewhere upgrades from this page. Deltas are arithmetic
facts of the identities (same workload shape, same payload size), not
performance comparisons.

## What this cell contains

The L0.5 family is the serialized-pipelined-ring AllReduce (backend
module `analytical_l05`, second frontier F1): the SAME unidirectional
ring, workload shape and equal-chunk construction as the L0 ring, with
each of the 2·(r−1) chunk transfers charged an explicit service time —
serialize the chunk at the transmitting NIC, occupy the link, one hop
latency per transfer:

    chunk size         c = M / r                       [c integral: r | M]
    one transfer       s = c/I + c/B + L               [one ring hop]
    completion time    t_L05(M, 4) = 2*(4-1)*s = 6*(M/(4I) + M/256 + 200)

At rank class 4 this family declares exactly ONE identity
(`allreduce_ring_l05` on the serialized-ring fabric,
`experiments/topologies/ring4_l05_free_params.yaml`); the I -> infinity
limit of the SAME identity is the L0 ring baseline itself (the module's
convergence anchor, pinned as an exact identity by the landed golden
tests), so the baseline this page deltas against is the I = infinity
member of this very family — the only 4-rank cell whose baseline is an
in-family limit rather than a different algorithm.

Identity executed (per op, message M, ranks r = 4, exact Fractions):

    per-rank wire traffic  T(M, 4) = 2*(4-1)/4 * M = 3M/2            (UNCHANGED from the L0 ring — serialization moves no bytes)
    completion time        t_L05(M, 4) = 2*(4-1)*(M/(4I) + M/256 + 200)
                                        = 3M/64 + 1200 ns            (I = 64 bytes/ns)
    serialization term     t_L05 - t_L0 = 2*(4-1)/4 * M / I = 3M/128 ns (exact, re-checked per op by the model)

Free parameters (equal across every config in this cell, and equal to
the other atlas rank classes): B = 64 bytes/ns, L = 200 ns, ranks = 4,
W1 Dense TP Decode shape (layers 2 x steps 3 = 6 AllReduce ops per
config). **The L0.5 family's one additional free parameter — the
injection (serialization) rate I — is declared here explicitly: I = 64
bytes/ns**, chosen by the atlas fairness rule as the registered
convention value: A-L05-INJ (`experiments/vertical_slice/assumptions_l05.yaml`)
registers value 64, the one landed L0.5 topology
(`ring8_l05_free_params.yaml`) carries 64, and the GF-05 anchor
convention sets injection at line rate (`injection_bytes_per_ns: 100`
against B = 100). I = 64 = B: the serializing NIC runs at link line
rate. No prior atlas cell carries I, so this page's declaration IS the
family's atlas convention record (indexed in the catalog). All values
are free parameters or model arithmetic — none is measured or
standard-derived.

Four arithmetic facts drive the whole cell, all visible in the identities
(ring baseline: T = 3M/2, t_L0 = 3M/128 + 1200 — [4r-ring.md](4r-ring.md)):

1. **At I = B the serialized identity is the baseline with a doubled
   bandwidth slope: t_L05(M) = t_L0(2M) exactly** (3M/64 + 1200 =
   3·(2M)/128 + 1200, verified at all 12 grid sizes). The latency chain
   is UNCHANGED (2·(r−1)·L = 1200 — L0's "coarse" chain is what L0.5
   makes explicit as one L per transfer), so both curves share the exact
   M = 0 intercept and delta(0) = 0: the L0.5 curve leaves the baseline
   from the same point with twice the slope in M.
2. **The serialization term equals the ring's own bandwidth term at
   every M.** With I = B, 2(r−1)/r·M/I = 3M/128 = the bandwidth term of
   t_L0 — per transfer, c/I = c/B = M/256 (serialization and wire are
   each exactly half the non-latency transfer time). Hence the delta
   identity

       delta(M) = (t_L05 - t_L0) / t_L0 = (3M/128) / (3M/128 + 1200) = 1 - 1200/(3M/128 + 1200)

   which is exactly the LATENCY FRACTION of the baseline identity:
   the L0-vs-L0.5 disagreement at I = B is the share of the ring's
   completion time sitting in its latency chain. Strictly increasing,
   bounded in (0, 1), delta(0) = 0, large-M limit exactly 1.
3. **Every delta is positive — this is the only landed 4-rank family on
   the slower side of the baseline.** Ring, crossbar, torus, doubling and
   phases all delta negative against the ring AllReduce; L0.5 pays a
   strictly positive serialization term at every M > 0 and every finite
   I, by the module's pinned convergence identity. The catalog's slower
   side is populated by this cell alone.
4. **M = 51200 B is now a four-fold special point of the 4-rank atlas,
   and L0.5 adds one new one.** At the ring's own balance point (bandwidth
   = latency at M = 51200, already the torus crossover and the ring-phase
   balance point), delta = exactly +1/2 — the serialization disagreement
   there is exactly half the baseline completion time. The L0.5 identity
   balances its own combined bandwidth+serialization term 3M/64 against
   1200 ns at M = 25600 B, inside the ladder's first x4 interval
   (16 KiB -> 64 KiB). The 4-rank transition ladder now reads
   {51200/3 (crossbar AR), 102400/3 (doubling AR, doubling phase), 25600
   (L0.5 at I = B), 51200 (ring AR, ring phase, torus crossover)} B.

One-in-parameter interpolation (arithmetic fact of the family, not a
sweep): t_L05 is linear in 1/I, pinned at the two ends by the convergence
anchor — I -> infinity returns the baseline identity exactly (0
serialization), the executed grid is I = 64 — and every finite I lands
strictly above the baseline at M > 0. The cell executes one I value
because the fairness rule fixes every free parameter across a cell's
grid; the 1/I ladder is recorded as the family's shape, not a landed
column.

Execution reachability (structural finding — the third and strongest form
of the reachability pattern): the L0.5 module is deliberately unregistered in BOTHs*
run-path registries by its own scope fence ("run-path/golden
integration is a separate capability-gated step"). Live attempts
before this cell was executed:

- sweep runner — `unknown algorithm(s) ['allreduce_ring_l05'];
  registered: ['allreduce_crossbar', 'allreduce_recursive_doubling',
  'allreduce_ring', 'allreduce_torus2d']`;
- run path — `unknown backend(s) ['analytical_l05']; registered:
  ['analytical_l0', 'analytical_l0_crossbar', 'analytical_l0_phase_collectives',
  'analytical_l0_recursive_doubling', 'analytical_l0_torus2d',

4-rank doubling was sweep-reachable/run-unreachable; 4-rank phases
run-reachable/sweep-unreachable; 4-rank L0.5 is reachable through NEITHER

## Crossover message sizes

**None in this cell.** A crossover is a payload size where two
identities in one cell swap ordering. The cell contains one declared
finite-I identity; the family's only other member is the I -> infinity
limit, which IS the ring baseline (an exact equality, not a crossing —
the serialization term is strictly positive at every M > 0 and finite I,
zero only in the limit, so the two curves touch only at M = 0 and never
swap). Against the baseline the delta is positive and strictly
increasing on the whole grid — sign never changes, no crossing exists.
Recorded honestly rather than forced; the 4-rank catalog's non-trivial
crossover remains the torus cell's M = 51200 B
([4r-torus.md](4r-torus.md)), which fact 4 above shows is also this
cell's delta = +1/2 point.
