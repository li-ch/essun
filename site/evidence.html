Reproducibility

Evidence: run id or it didn't happen

Every execution stores a content-addressed record — run.json + observations.json under results/<run_id>/, the id a SHA-256 over the run's content. Same manifest, inputs, and code: same id, byte-identical records. A different id means different inputs. That property is what makes an id citable.

The vocabulary

The evidence ladder

Five labels, equal status, one line each. The two upper rungs carry a not yet attained mark — that mark is itself a statement about repository state, and it comes off only with an evidence record to cite.

PROPOSED

Design only, no result claimed.

IMPLEMENTED_UNVERIFIED

Code runs; semantic checks incomplete.

VERIFIED

Checks pass in declared scope. In this repository's usage: reproduced outside the author's working tree (a human or CI, from a fresh clone).

CALIBRATED not yet attained

Held-out empirical validation inside a stated domain. Unused by essun today — nothing in the repository is calibrated against hardware.

EXTERNALLY_REPRODUCED not yet attained

Independent reproduction from released artifacts. Unused by essun today.

The ceiling for the entire repository today is IMPLEMENTED_UNVERIFIED. A result may carry different labels for different claims; commits are read as claims and carry the label in their title. When a document cites earlier labeled work, it reproduces the label it carried — a citing party cannot upgrade it.

Run records additionally request an evidence level E0–E4: E0 = identities and determinism (no empirical claim), E1 = calibration candidate, upward toward external reproduction. Everything demonstrated on this site is E0.

The machinery

Byte-identical replay and goldens

  • Determinism is a house rule: fixed tie-breaking, partitioned RNG streams, integer byte counts; seed, topology, hashes, and config stored with every run. Reruns are replays, not new measurements.
  • Golden tests spell expected values in the test source, derived by hand from closed-form identities — never pasted back from the implementation's output. tests/golden/ holds the pattern; tests/determinism/ replays runs and sweeps.
  • Goldens are pinned by run id: make demo fails outright unless the L0 run reproduces 146ba565… (pinned in experiments/vertical_slice/w1_decode_smoke.GOLDEN.md) and the discrete-event twin reproduces the id pinned in tools/make_figure.py (ASTRA twin c6dc87eb…, uet twin fbb46d16…).
  • One command demonstrates the chain: make demo runs bootstrap-if-needed → schema checks → the test suite → both golden-run equality checks → a design-space sweep → figure registration → the paper-claims check, and exercises its own cold-tree (git archive HEAD) rebuild on every run. A cold-tree run completes in ~11 s with Docker, ~10 s in no-Docker mode.
  • Claim links: every stored run is claim-linked in the append-only, content-addressed evidence store (src/essun/evidence/store.py), with classified counterexamples and content-addressed figure registration.

Words under discipline

Claims discipline

  • The paper skeleton carries [RESULT: metric, experiment, status] placeholders; numbers appear only when an immutable run record exists.
  • make paper-check enforces the discipline mechanically: fabricated-number detection, a frozen hype vocabulary (checked in every inflection the review rounds added), and figure-reference rules — over paper/ and the README gate section.
  • The counterexample policy is minimize_then_refine: when backends disagree, minimize and classify the counterexample before any parameter is touched. Verification is not validation.

Stated plainly

What the demo does not show

Stated plainly, because softening any of these while the state is unchanged would make the site dishonest — each line flips only with an evidence record to cite:

  • The UEC profile's semantics bind documentation and L1 contracts today; they do not yet change any L0 number — every numeric model value stays an explicit free parameter.
  • The cross-standard table (UEC vs paper-derived UnifiedBus) is parameter-flavored: both columns share the same free parameters, so its delta is zero by construction.
  • Nothing is calibrated against hardware: the evidence ceiling is IMPLEMENTED_UNVERIFIED and the calibration plan is unexecuted.
  • A normative second standard is blocked on license review (UALink/OCP/CXL restricted texts were never fetched).
  • The automated counterexample-guided refinement loop is design on paper; blind evaluation has not been run.
  • "Implemented and tested" means code exists and tests exercise it. It does not mean agreement with any physical fabric.
  • Workload coverage is the dense tensor-parallel family (W1 decode, W2 prefill). Executing MoE (W3) and PD/KV (W5) traffic needs L1/L2 backends that do not exist yet; their manifests are rejected loudly.
  • UALink and CXL are license-restricted and were never ingested; license review precedes ingestion of any standard text.
