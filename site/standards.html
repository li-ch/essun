Standard profiles

Standard semantics, separated from modeling assumptions

essun never invents a normative value. Every standard-derived value keeps a source anchor (version, section, hash); where a standard does not fix a number, the model uses an explicit free parameter. License review precedes ingestion of any standard text, and restricted texts are never fed into any pipeline.

Three rules

The discipline

  • Separation rule. Standard targets, implementation profiles, and modeling assumptions are three different things; the repository keeps them in separate files, and the reconciliation ladder checks every model assumption against the standard profile explicitly.
  • Anchor integrity. Each anchor in a registry carries a verbatim quote, page number, and page sha256; the test suite recomputes page hashes and quote matches (a permanent license-gate test).
  • Free parameters stay free. After the UEC 1.1 reconciliation, still no numeric L0/L0.5 model value is standard-derived: link bandwidth/latency and workload sizes remain explicit free parameters in the assumptions registries (assumptions_l0.yaml, 26 entries; assumptions_l05.yaml, 6 entries; all PROPOSED pending review).

Read this one honestly

Cross-fabric comparison — which profile outperforms which, under stated assumptions

The question we hear most often — which fabric outperforms which — has an honest answer only after the inputs are pinned. Under the fairness bar below, every honestly computable comparison between the two profiles fits one matrix: five observable axes against three profile pairs, fifteen cells in all. Of the fifteen, twelve cells are comparable and restate two findings — the delta-zero tie and the window saturation boundary; one cell is NOT COMPARABLE and two are NOT SAMPLED, each with its reason stated in place. Everything here is evidence level E0 PROPOSED: closed-form analytical identities under declared free parameters, ranking model identities rather than hardware, with nothing measured on any system.

What a fair comparison requires

  • Identical open choices. Both profiles consume the one shared free-parameter record — B = 64 bytes/ns and L = 200 ns fed unchanged to every flavor file. Neither the public UEC 1.1 text nor the five public UnifiedBus papers anchors a per-lane rate or per-hop latency usable at this fidelity, so a ranking that differed through those inputs would be an artifact of unequal inputs, not of the fabrics.
  • Pinned sources. The UEC side runs the license-cleared UEC 1.1 semantic profile; the UnifiedBus side is a paper-derived design profile from five public papers — not a normative standard profile, because the specification track stays license-gated. UALink and CXL have no profile at all (license-blocked, never ingested).
  • Mechanisms stated, not smuggled. The one executed mechanism asymmetry is the UEC TFC credit window (admission law UEC11-FC-R02); the UnifiedBus side carries no window because its public sources are silent on flow control (UBP-F04) — declared silence, not a modeling shortcut.
  • Same workload, one operating point per artifact. The same-workload gate pins one W1 Dense TP Decode shape (2 layers × 3 steps = 6 AllReduce ops) and one tp_size per artifact, so every delta compares the same work.

Delta zero, by construction

The grid experiments/sweeps/cross_design_uec_vs_ub_paper_l0_v1.yaml compares the UEC-flavored and paper-derived-UnifiedBus-flavored columns on shared L0 free parameters. Both columns share the same free parameters, so the UnifiedBus row coincides exactly with the identity-matched UEC control: delta 0 is an arithmetic fact of the construction, not a measured difference between standards. A real cross-standard numeric comparison becomes possible only when standard-derived values exist — which today none do.

The one executed mechanism

The one executed mechanism that separates the profiles at this fidelity is the UEC transport flow control admission law (requirement UEC11-FC-R02): a source must not transmit bytes it holds no credit for. The closed form says the windowed ring ties the unwindowed ring exactly when the granted window covers the bandwidth-delay product, W ≥ B·(L + Lcr), and ranks strictly worse below it, with a penalty proportional to the shortfall. At our shared operating point the boundary sits at exactly 25600 bytes — 100 UEC credit units — and the windowed side is never faster at any sampled point, so the transition is a saturation boundary rather than a ranking crossing.

The boundary carries no message and no rank term: it did not move when we changed payload (1 MiB and 16 MiB) or rank count (256 and 1024), while the penalty scaled from 3240864 ns to 51853824 ns at the worst sampled window, both at 1024 ranks. Read in the shared axes, the same boundary becomes a provisioning rule: with the window fixed at 25600 bytes, the tie holds at and below B = 64 B/ns and at and below L = 200 ns, because one fixed window stops covering the product exactly when the credit-loop round trip exceeds W/B = 400 ns. We state the threshold exactly because the platform computes it exactly; what the matrix never shows is the windowed side winning.

The matrix

The columns are three pairs. The two-profile pair sets the UEC profile's flagship executed semantic — the TFC window admission law (UEC11-FC-R02) — against the UnifiedBus paper profile's ring stand-in with no window. The mechanism ablation controls for that pair: the same windowed ring against its own unwindowed twin, isolating the admission-law term. The anchor pair matches identities at the rack scale the UnifiedBus paper fixes — 64 NPUs per rack (UBP-P17) — where the delta-zero tie lives.

The comparable cells restate the two findings above, and the empty cells matter just as much. Where a mechanism is absent on one side — the window axis for the unwindowed pair — the cell reads NOT COMPARABLE with the reason stated in place. Where the axis is comparable in principle but no artifact samples it for that pair, the cell reads NOT SAMPLED rather than inventing a number; honest empties are part of the deliverable.

What the matrix does not compare

  • One mechanism axis. Only the TFC credit window separates the profiles at this fidelity; its cell-quantization and packet-overhead laws (UEC11-FC-R08/R09) refine the windowed side only and appear in no cross cell.
  • UALink and CXL: no column. Their specification documents are license-restricted and were never ingested, so no pair and no cell exists — any UALink or CXL comparison number from this platform would be fabricated.
  • Hierarchy and multi-level fabrics. The UnifiedBus paper's hierarchical full-mesh with asymmetric per-level widths, memory semantics, APR routing, and the pod-of-racks hierarchy need a fidelity no landed backend executes yet.
  • Congestion, packetization, and collective overlap are out of scope at this fidelity — declared unsupported by every backend involved.
  • No claim label upgrades. The page derives its verdicts from committed artifacts; it upgrades no claim's evidence label, and the two window columns agree by the declared UBP-F04 silence, not by evidence about UnifiedBus hardware.

Boundaries

What is deliberately out of scope today

  • UALink and CXL are license-restricted and were never ingested. The normative upgrade of public-gate leg 2 stays blocked on the license review; UEC remains the only license-cleared normative profile.
  • No FLIT-level standard semantics are modeled yet; the UEC profile binds documentation and L1 contracts today — it does not change any L0 number.
  • Where a standard fixes no value, the repo records an explicit free parameter rather than guessing one — the divisibility guards, bandwidth, latency, and injection rates are all yours to set, and the run id changes when you do.
