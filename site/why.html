The problem

Fabric decisions, answered with numbers anyone can re-derive

essun is built around one idea: a single executable specification drives every fidelity, from closed-form analytical models to discrete-event simulation — with explicit observables, validity domains, and recorded provenance.

The situation today

Vendor slides and one-off simulators

Companies choose among scale-up fabrics — which protocol to adopt, which topology to wire, which collective algorithm to schedule — using one-off simulators and vendor numbers. Those comparisons are not apples-to-apples, and published comparisons rarely state their inputs completely enough to reproduce.

essun's answer is a specification, not a benchmark number: the experiment manifest and its input files are the executable specification, and every fidelity reads the same one.

Two rules, house law

What follows from that idea

Rule one

Every number traces to an immutable run record

Runs are content-addressed: the same manifest, inputs, and code always produce the same run id and byte-identical records. Paper-facing numbers stay [RESULT: metric, experiment, status] placeholders until such a record exists.

Rule two

When simulators disagree, classify — do not tune

The cross-backend difference engine decomposes gaps into declared modeling differences with an anti-tuning gate; a plausible curve is never treated as semantic correctness.

Where this goes

The end game

Fabric decisions in AI infrastructure are still made from vendor slides and one-off simulators. We want to end that. ESSUN's answer is a portable contract between four things: what a specification says, what an implementation may choose, what a simulator actually models, and what the resulting evidence supports. One experiment manifest drives every fidelity, every emitted number traces to a content-addressed run record, and every claim carries an evidence label — so fabric decisions can be answered with numbers anyone can re-derive.

The strategy is profile-led and engine-plural: profiles, semantic bindings, and evidence records should matter more than which engine executes them. A project becomes infrastructure only when others depend on it and can maintain it — the roadmap is an experiment in earning that dependence, with falsifiable exit conditions at every phase. The end game: scale-up fabric evolution becomes evidence-driven, the way model development became benchmark-driven. Read the full vision and roadmap.

Not a replacement

Where essun sits

essun does not replace general-purpose network simulators — two of its discrete-event backends are pinned, credited external simulators run under one manifest. For a factual side-by-side with ASTRA-sim, ns-3, OMNeT++, HTSim, and Batfish, including where each is the stronger tool, see the Comparison page.

The two rules above are enforced mechanically rather than by convention; the Evidence page documents the machinery, and the Quickstart page shows both rules firing in a real run.
