Quickstart

From clone to a reproduced run record

Three commands to install and replay the public-gate chain; then a walkthrough of your opening experiment — run a committed workload, read the record, check it by hand, and change one free parameter.

Before you start

Requirements

  • Python 3.10 or newer (pyproject.toml requires-python; the CI matrix runs 3.10–3.13). Needed by make bootstrap.
  • Docker — optional. Docker is needed only by the two discrete-event legs of make demo (the ASTRA-sim container run and the figure registration that renders from its record). Any recent Docker Engine with bind-mount support works; verified with Docker CLI/Engine 29.8.2 (OrbStack) on macOS arm64. When the docker CLI is absent or the daemon is unreachable, make demo runs in no-Docker mode: every L0-only leg runs unchanged, the two Docker-dependent legs are skipped with exactly what was skipped and the requirement printed, and the command exits 0. A present-but-missing pinned image is not skipped — the run stops there naming the rebuild step.
  • The pinned image essun/astra-sim-analytical:s1 (id sha256:bb02b612…, ~1.3 GB, linux/arm64, local-only — never pushed): build it from backends/docker/astra-sim.Dockerfile per the runbook. The recorded build log sums to about five minutes of step time on the reference Apple-silicon Mac; on x86-64 hosts, rebuild from the same Dockerfile (the pinned ubuntu:22.04 base is multi-arch).
  • Disk: repo export ~48 MB of tracked blobs (the git archive zip is ~8 MB) + venv ~36 MB + content-addressed results/ < 1 MB after a gate run + the ~1.3 GB image when built.
  • Time (reference machine, 2026-10-28): a cold-tree make demo completes in ~11 s with Docker, ~10 s in no-Docker mode.

Requirements above carry the evidence label IMPLEMENTED_UNVERIFIED — measured on the reference machine, warm pip cache; a fresh machine adds package download time.

Three commands

Install

sh 
$ git clone https://github.com/li-ch/essun && cd essun
$ make bootstrap    # creates .venv, installs the package + dev deps
$ make test         # 717 passed, 1 skipped on the reference machine

make bootstrap creates a local virtual environment and installs the package in editable mode with dev extras (pytest). Nothing is installed globally and no compiler toolchain is needed for the analytical backends — they run in-process, in Python.

Your opening experiment

Walkthrough — run a committed experiment

One experiment = one YAML manifest referencing five input files by repo-relative path (workload, fabric topology, standard profile, implementation profile, assumptions registry), naming one backend, and listing the observables to emit. make run validates the manifest against schemas/experiment.schema.json, gates capabilities, executes, and stores a content-addressed record.

  1. 1

    Run the golden smoke experiment

    make run EXP=experiments/vertical_slice/w1_decode_smoke.yaml

    Output (the run id is pinned in experiments/vertical_slice/w1_decode_smoke.GOLDEN.md):

    {
  "run_id": "146ba565d2cac8e613435e548caba4f606e0abbb149beaf6404935d4f92199a1",
  "run_dir": "results/146ba565d2cac8e613435e548caba4f606e0abbb149beaf6404935d4f92199a1"
}

    This is the W1 Dense TP Decode workload (6 AllReduce ops of 16 KiB) on the committed 8-rank ring (bytes_per_ns: 64, hop_latency_ns: 200).

  2. 2

    Read the record

    python3 -m json.tool results/<run_id>/observations.json

    The interesting parts: O-CCT completion time is 3248 ns per op (exact fields ride alongside every float — completion_time_ns_mean_exact: "3248"), and O-CONSERVATION reports 0 violations over the wire-byte accounting.

  3. 3

    Check it by hand

    The whole point of an analytical backend is that nothing is opaque. The L0 ring closed form:

    t(M) = (2·(r−1)/r · M) / B  +  2·(r−1) · L
       └── transfer term ──┘    └─ latency ─┘

r=8, M=16384, B=64, L=200:
  28672 B / 64 B/ns + 2800 ns = 448 + 2800 = 3248 ns

    28672 = 2·7/8 · 16384 bytes of per-rank ring traffic; 2800 = 2·7·200 ns. If your arithmetic and the record ever disagree, that is a model bug, not a tuning knob — conservation violations raise instead of degrading.

  4. 4

    Prove it is deterministic

    Run step 1 again: the output is byte-identical, the same run_id. Reruns are replays, not new measurements. Change any input byte (say hop_latency_ns: 201) and the id changes — content addressing means a run record can never silently refer to inputs it did not have.

  5. 5

    Make it yours

    Copy the topology file, change one free parameter (e.g. halve bytes_per_ns: 64 → 32), point a copied manifest at it, rerun: the completion time moves to exactly the value the closed form predicts (3696 ns at B=32), wire bytes unchanged, because bandwidth changes time, not traffic. The full two-example guide — run your own topology, then write your own workload and manifest field by field, with every command's real output pasted — is docs/usage.md in the repository.

Safety rails

What the capability gates catch for you

Gates fire before any model executes; a bypass is treated as a bug, never a feature. Two you are likely to meet:

  • Rank mismatch — a topology of 9 ranks with a tp_size: 8 workload fails loudly: workload tp_size 8 != topology ranks 9.
  • Non-integral chunking — L0 models require the rank count to divide every payload (A-L0-DIV); a 7-rank ring with a 16384-byte op is rejected with the assumption id and the reason.

Undeclared (model, topology_class) pairings, unknown backends, workloads issuing collectives the model does not declare, and unsupported observables all fail the same way: named gap, non-zero exit.
