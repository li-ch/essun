The CSIG-Term() function does the following: 
• Extracts the information carried in the CSIG tag (csig.t, csig.s , csig.lm, csig.d bit) 
• For a packet arriving on a transport flow using receiver-based congestion control, presents the 
extracted CSIG tag information to the receiving FEP’s transport layer (for onward delivery to the 
CC algorithm and/or receiver-based application) 
• For a packet arriving on a transport flow using sender-based congestion control, presents the 
extracted CSIG tag information to the CSIG-Reflect() function in the receiving FEP’s transport 
layer, to allow return of the CSIG tag information to the flow’s sending FEP 
• Strips the CSIG tag from the incoming packet 
 
See Section 4.2.5.5.1 for a description of the CSIG-Reflect() function. 
4.2.5.5.1 Reflection 
When a CSIG-tagged packet from a source FEP arrives at a destination FEP that is CSIG-enabled, the 
CSIG-Term() function at the destination FEP extracts the CSIG tag information and passes it to the 
transport layer. If the transport layer is using a sender-based CC algorithm (such as NSCC), or other 
sender-based functions (such as multi-path load balancing) that need the information in the CSIG tag, 
the CSIG-Reflect() function at the transport layer MUST be enabled. The CSIG-Reflect() function 
populates the CSIG Reflection Header with information extracted by the CSIG-Term() function. The CSIG 
Reflection Header is returned to the source via an ACK or NACK packet generated by the transport layer. 
This enables the source FEP to receive feedback on path conditions indicated by the CSIG tag received at 
the destination. Section 3.6.9.4 describes the format of the CSIG Reflection Header as well as the 
pds.ack_ccx_state and pds.nack_ccx_state formats used for CSIG reflection. 
Implementation of the CSIG-Reflect() function is REQUIRED in a CSIG-capable FEP. 
Figure 4-7 shows the logical interactions among the CSIG-Term(), CMS, PDS, and CSIG-Reflect() functions.  
The detailed implementation of the CSIG-Reflect() function depends upon the congestion control 
algorithm in use. Detailed procedures for constructing the CSIG Reflection Header in the ACK_CCX and 
NACK_CCX fields, setting other transport header fields, and their use in particular congestion control 
algorithms (e.g., NSCC and RCCC) are specified in 3.6.9.4. 
4.2.6 CSIG Tag Layout 
The CSIG tag lies within an Ethernet frame’s layer 2 headers. An EtherType unique to the deployment 
(4.2.4.1.1) identifies a CSIG-tagged frame. 
When layer 2 encapsulation (e.g., IEEE Std 802.1ad or stacked tags) is not in use on a frame, the CSIG tag 
is always placed as the last tag in the layer 2 header. Tunneling of CSIG-tagged packets at layer 2, layer 3, 
or above is out of scope of this specification.
