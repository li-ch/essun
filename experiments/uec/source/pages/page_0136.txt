However, the library and API have evolved to support additional high-performance transports and NICs.

Today, verbs can be viewed as defining software primitives for NIC hardware supporting one or more of 
the following: 
• NIC hardware queues are directly accessible from user space. 
• NIC hardware can directly access application memory buffers. 
• Transport supporting RDMA operations. 
Even the meaning of RDMA has evolved to refer to the key features of devices that support RDMA 
transports and not just the transport operation. 
The impact of integrating UET support into verbs is that UET concepts will adopt RDMA naming. 
However, such naming should not be interpreted as requiring that UET must adhere to RDMA 
semantics, as RDMA objects have evolved beyond their original definitions. Select RDMA objects are 
defined in the following section. 
2.3.2 Verbs Overview 
Conceptually, “verbs” is an abstract description of the functionality of an RDMA NIC. RDMA verbs is an 
API definition of that abstraction, with these general characteristics: 
• The API is device-centric. Functions map to a specific NIC. 
• There is an identifiable mapping between API calls and transport operations and fields. 
RDMA verbs defines several objects that are relevant for UET verbs. These are highlighted in Table 2-45 
with applicable implementation details.
