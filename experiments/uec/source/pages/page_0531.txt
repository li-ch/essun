3.6.18.4.6 Vendor-specific Signals 
Any implementation MAY support vendor-specific signals. Their names MUST be prefixed with <vend>, a 
vendor-specific alias encoded in the variable name, e.g., uet_tx_ack_vend_<signal_name> or 
uet_rx_req_vend_<signal_name>. The <signal_name> MAY encode any additional information such as 
vendor name. 
3.6.18.5 Triggers 
Algorithms request invocation when an accumulator matches their criteria, as determined by triggers. 
Every trigger is associated with a single accumulator instance and is identified by a trigger identifier. The 
set of triggers available to an algorithm, and their association with accumulation functions and signals, is 
defined by the algorithm’s YAML configuration profile. Triggers cannot be created or deleted at runtime, 
but an algorithm can modify them to change their configuration and match criteria. 
Triggers are defined in the YAML specification and given a macro name to reference them from the 
algorithm code.
