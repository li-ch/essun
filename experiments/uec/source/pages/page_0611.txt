4.2.4.1.8 Do Not Modify (csig.d) 
The csig.d bit provides a Do Not Modify indication for a CSIG tag. When a switch receives a CSIG tag with 
csig.d = 0, that switch MUST, according to the signal type (csig.t) specified in the tag and the signal 
type’s aggregation function, perform CSIG-Compare-and-Update() on the signal value (csig.s) in that tag. 
When a switch receives a CSIG tag with csig.d = 1, that switch MUST NOT modify the signal value (csig.s) 
in that tag. When a CSIG tag is first initialized, its csig.d bit MUST be set to zero, to indicate that 
receiving switches are permitted to update the signal value in that tag. 
In a UE fabric configured to perform packet trimming and that supports CSIG, all switches MUST support 
the following base case behavior: When a CSIG-tagged packet arrives at a heavily congested queue, and 
the receiving switch trims the packet, that switch MUST set the CSIG tag’s csig.d bit, and SHOULD make 
no further modifications to the CSIG tag. Some deployments MAY overwrite the CSIG tag’s signal value 
(csig.s) with signal information from the switch where trimming occurs; this policy may benefit 
congestion control at endpoints. Those use cases and their configuration are outside the scope of this 
specification. 
A CSIG-capable switch may support configurations in which it does not set the csig.d bit when trimming 
CSIG-tagged packets. Those use cases and their configuration are outside the scope of this specification. 
Moreover, all UE-compliant switches that support CSIG MUST support the base case behavior of setting 
the csig.d bit in the CSIG tag on any packet they trim.
