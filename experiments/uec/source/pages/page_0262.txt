Figure 3-36 - Deferrable Sends, Unexpected Message Case 
A final variation on deferrable sends is illustrated in Figure 3-37. In this scenario, the target does not 
reserve the buffer when a matching buffer is posted. This means that a deferrable send can be started, 
deferred, restarted, and redeferred. This sequence can occur an indefinite—even infinite—number of 
times. The lack of a reserved buffer is indicated by the passing of a target restart token of 0. A target 
restart token of 0 MUST NOT be used for a reserved target buffer. In Figure 3-37, message ID 1 is reused 
for the third transmit of the deferrable send, since that message ID was no longer in use for an in-flight 
message.
