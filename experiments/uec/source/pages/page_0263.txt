Figure 3-37 - Deferrable Sends, Unexpected Message Case, No Reserved Buffer 
Implementation Note: 
Implementation of the expected message case for deferrable sends is relatively straightforward. The 
unexpected message case—where the deferrable send is deferred—requires a little more care. 
While there are many choices an implementation can make, this note provides guidance for an 
implementation that could be used. It is necessary to achieve several things with an implementation: 
1. The first packet of the deferrable send to arrive at the target must be identified as a new 
message. 
2. Subsequent packets of the deferrable send must be correlated with the first transmission of the 
message. 
3. It must be possible to identify the first packet of the restarted deferrable send as a restart at the 
target.
