The CSN is incremented by broadcast collective operations even if no message is received, ensuring 
global synchronization. Non-root FEPs in a broadcast collective operation increment the expected CSN 
without receiving a message, ensuring subsequent CSNs align. The CSN is incremented by all ranks for 
each new collective operation. 
If data arrives at the receiving FEP and a buffer is not available, the FEP generates a response indicating 
the event (see Section 3.4.5.4). 
Because deferrable send is used, packets are retransmitted with new pds.psn values when delivered to 
SES and acknowledged. A NACK is not generated when a message is deferred; the defer is 
communicated via the SES response in an ACK. 
Sending the RTR message optimizes latency as compared to waiting for a pre-configured time. If the 
buffer is posted more quickly than the ‘buffer-not-ready’ timer, the RTR message will trigger 
retransmission faster than waiting for the configured time period. The timer becomes a backup to the 
RTR message, as not all FEPs support generation of UET_DEFERRABLE_RTR.

the message and return RC_UNSUPPORTED_OP (see Table 3-25). 
2.4.11.2 Packet Delivery and Congestion Management 
INC uses ROD PDCs, which provide in-order delivery of requests and responses. Reserved PDCs are used 
to simplify the SEP. Each INC communicator is allocated an individual PDC. 
INC PDCs may optionally use UET transport flow control (TFC–See Section 3.6.15), allowing the receiving 
SEP or FEP to constrain in-flight data on a PDC based on buffer availability. 
No special PDS or CMS features are required to support INC. UET profiles supporting INC MUST support 
reserved PDCs.
