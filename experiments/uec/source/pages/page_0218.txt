The standard SES header carries a ses.message_id that is carried back to the initiator in the SES

3.4.3 Semantic Header Formats 
Several header formats are needed to implement UET. Those formats are shown here in both illustrated 
and tabular forms. Some header fields (e.g., ses.opcode) use enumerated types defined in Section 3.4.7. 
All reserved fields MUST be set to 0 and ignored upon receipt. Header formats are selected based on the 
guidelines in 3.4.3.8. 
3.4.3.1 Standard Header Format 
The standard header format shown in Table 3-9 is used for most operation types. Table 3-9 illustrates 
the fields present when ses.som is set to 1, and Table 3-10 presents the slight variation on the header 
for when ses.som is set to 0. Implementations MUST support using the UET_HDR_REQUEST_STD format 
for any request operation in the AI Base, AI Full, and HPC profiles. It is used for any multi-packet 
operation and for any operation that requires matching criteria—including those that need a full 
memory key as part of implementing fi_write() or fi_read(). Either the UET_HDR_REQUEST_STD or the 
UET_HDR_REQUEST_MEDIUM header in Figure 3-16 MUST be used when completion data is needed.
