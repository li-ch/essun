Whether a switch supports processing of a new signal type is NOT discoverable through LLDP. Such 
discovery is not necessary, as a switch receiving a packet with a CSIG tag for an unsupported signal type 
can still parse and forward the packet correctly. Instead, the central management entity is responsible 
for configuring switches that receive a packet with a CSIG tag for an unsupported signal type to either 1) 
CSIG-Strip-and-Forward() the packet or 2) CSIG-Forward() the packet while preserving the CSIG tag 
unchanged. A deployment will specify which one of a few policies to follow when a switch receives a tag 
for a signal type it does not implement (e.g., Forward() without updating the tag or CSIG-Strip-and-
Forward()).
