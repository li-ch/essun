If pds.flags.ar is not set on the CSIG-tagged packet, the destination FEP may employ other 
implementation-specific policies to determine when to reflect CSIG information. For example, the FEP’s 
policy may reflect only when the received signal value is over or under some configured threshold. 
Determining when to reflect CSIG information when CSIG-tagged packets arrive without pds.flags.ar set, 
or when ACKs are coalesced, is outside the scope of this specification. 
3.6.4.8.1 Reflection Header in UET 
The 64-bit CSIG Reflection Header is carried in the pds.ack_ccx_state and pds.nack_ccx_state fields of 
ACK_CCX and NACK_CCX packets, respectively. FEPs copy the tag data portion of the CSIG tag (2 B for 
the compact and 6 B for the wide CSIG tag, excluding the TPID) into the least-significant bytes of the 
CSIG Reflection Header, and they set the most significant 4 bits of the CSIG Reflection Header to indicate 
the CSIG tag type. Refer to CMS Section 3.6.9.4 for a description of the CSIG Reflection Header fields. 
3.6.5 UET CC Protocol Operation Overview 
The UET Congestion Control protocol, UET-CC, as defined in this specification, provides congestion 
management on a best-effort Ethernet network. 
3.6.5.1 Types of Congestion [Informational] 
Congestion control is a key component required to enable best-effort network operation in large 
datacenter networks. While PFC is useful for certain use cases, large-scale PFC deployments suffer from 
various pathologies that are well documented in the literature [15], [1]. UET can operate with both 
lossless and best-effort networks; this specification refers to best-effort networks, so avoids these issues 
by design.
