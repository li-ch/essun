2.4.2 Theory of Operation 
The IM establishes a communicator by grouping member FEPs and associating the group with a SEP, 
assigning a unique collective ID (CID) upon creation. The INC switch uses the CID to disambiguate 
communicators. The INC switch filters packets based on JobID/CID combinations. 
Some applications require specific orders of operator application. Optionally, each communicator can 
have constraints on the order of operations. 
Upon communicator creation, the CSN is set to 0. The establishment of the required transport resources 
is coordinated by the IM, as described in Section 2.4.12. 
When a new operation is started, a rank uses the current CSN and increments it by one, wrapping from 
the maximum 12-bit value back to 0. To start a collective operation, a rank issues a 
UET_DEFERRABLE_SEND with the defined INC field (see Section 2.4.11.1) that encodes the CSN, type of 
operation, and necessary parameters.  
The SEP receives the input data, performs the operation defined by the INC field on the group identified 
by the CID, and sends the output data to the recipients. The recipients of the output data depend upon 
the operation.  For example, the allreduce collective requires the SEP to send the data to all ranks of the 
communicator. The reduce collective requires the SEP to send the data to only one specified root node.
