3.5.11.8.6 pds.flags.req 
This 2-bit pds.flags.req field in the RUD/ROD/RODL ACK is used to indicate the target has a request for 
the initiator. An initiator always sets the pds.flags.req field to zero. The field is defined as:

3.5.11.8.7 pds.flags.p 
The probe (pds.flags.p) flag is used in an ACK message to indicate the ACK was triggered by a Probe CP. 
The ACK_PSN value is not valid when the pds.flags.p flag is set.  
3.5.11.8.8 pds.flags.nt 
The NACK type (pds.flags.nt) flag in the NACK header indicates the type of packet being NACK’d. If 
pds.flags.nt is cleared, the NACK is for RUD, ROD, or RODL. If pds.flags.nt is set, the NACK is for a RUDI 
packet. 
3.5.11.8.9 pds.flags.cack 
The pds.flags.cack field is used in the RODL general request format (3.5.10.5) to indicate that the 
pds.rev_cack_psn_lsb field is present and represents the lower 16 bits of the CACK_PSN for the reverse 
direction.  If the flag is cleared, the pds.clear_psn_offset is present and operates the same as with 
ROD/RUD. 
3.5.11.8.10 Reserved Flags 
Reserved flags are reserved for future use. Reserved flags are set to zero on transmission and ignoreded 
on receipt.
