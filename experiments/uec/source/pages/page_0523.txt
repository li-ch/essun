This accumulation operator conceptually requires floating point support, and all

When a new update to a congestion signal is received, the update is integrated into the current signal 
value using the predefined accumulation operation. The update occurs atomically, meaning that each 
signal update is applied without interruption, preserving data integrity and preventing partial 
modifications. Additionally, the update order is undefined, as PCM assumes associative operators, 
allowing updates to be applied irrespective of sequencing constraints. This may affect the accuracy of 
some operators that are not actually associative such as uet_op_ewma(). 
Furthermore, all signal updates originating from a specific source, such as an acknowledgment (ACK) 
packet, are processed atomically. This guarantees that multiple updates contained within a single packet 
are applied simultaneously before any subsequent packet influences the corresponding signals. For 
instance, if a packet carries updates to both an explicit congestion notification (ECN) signal and a round-
trip time (RTT) signal, both updates are applied at the same instant, ensuring consistency before any 
other packet modifies either of those signals. This atomic handling mechanism maintains consistency in 
congestion signal processing within UE's congestion management framework. 
Multiple accumulation operations (e.g. uet_op_last() and uet_op_sum()) may be defined for the same 
signal.
