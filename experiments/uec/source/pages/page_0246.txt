3.4.4.4 Unified Local Profile Response Generation 
Semantic responses to semantic requests that used the UET_HDR_REQUEST_LCL format use the 
UET_HDR_RESPONSE_DATA_LCL format. All responses to messages packed into a single PDS packet are 
returned in a single PDS acknowledgment. The acknowledgement to PDS can be a simple 
UET_DEFAULT_RESPONSE when a write transaction completes without encountering processing errors. 
In this case, a distinct acknowledgement packet need not be generated immediately, as a cumulative 
acknowledgement is sufficient. 
When a PDS acknowledgment packet is generated, it MUST contain one 
UET_HDR_RESPONSE_DATA_LCL for each UET_HDR_REQUEST_LCL packed into the corresponding PDS 
request packet. Any UET_HDR_REQUEST_LCL with a UET_READ or UET_FETCHING_ATOMIC opcode 
MUST generate a response using the UET_RESPONSE_W_DATA opcode. If any semantic request packed 
into a single PDS request packet requires a UET_RESPONSE_W_DATA opcode with a non-RC_OK return 
code, a PDS acknowledgement packet MUST be generated, and it MUST contain one semantic response 
for each semantic request that was packed into that PDS request packet. 
All semantic responses using ROD or RODL MUST be generated in order. A semantic response MUST 
NOT be generated until all required local processing has completed. Required processing includes local 
error detection, but excludes waiting for a completion unless ses.dc is asserted. For any semantic 
request with ses.dc set, the corresponding semantic response MUST NOT be generated until the 
completion has been received. 
Implementation Note: 
Examples of local completion include a PCIExpress UIO completion or an AXI completion.
